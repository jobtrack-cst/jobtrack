JT-74 adds Offer event processing without changing public operations or JT-45 eligibility.

- `application_consumer.go` binds only `application.submitted` on durable quorum queue `offer.applications`, through `events.Consume`. Invalid envelopes, producers, typed payloads and UUID fields are permanent failures. Database errors retry under the shared bounded retry/dead-letter policy.
- Migration `00004_events.sql` adds `processed_events` and `outbox_events`. Participants and deduplication claims commit together. Participants are immutable; conflicting participant data rolls back the claim and is a permanent failure.
- Offer creation and decisions insert typed outbox events in their state-change transactions. Outbox insertion failure rolls back the operation. Existing uniqueness, authorization and final-decision rules remain.
- Relay reads unpublished rows in insertion order, waits up to 10 seconds for confirmation, and marks after confirmation. Failed publishing drops the connection; the next attempt reconnects. A crash after confirmation before marking resends the same event ID. Downstream consumers must deduplicate event IDs. Published rows are retained. Multiple replicas may publish duplicates, matching the established relay pattern.
- Startup owns the consumer and relay, cancels and joins them before closing database resources. Existing Compose Offer configuration supplies RABBITMQ_URL through shared service environment and waits for healthy PostgreSQL/RabbitMQ; no Compose edits are required.

Final read-only SQL used (`/private/tmp/jt74_verify_outbox.sql`):

```sql
BEGIN READ ONLY;
SELECT o.offer_id, o.status, e.routing_key, count(*) AS event_count,
 bool_and(e.published_at IS NOT NULL
 AND e.payload::jsonb->>'producer'='offer'
 AND e.payload::jsonb->>'type'=e.routing_key
 AND e.payload::jsonb->>'event_id'=e.event_id::text
 AND e.payload::jsonb->'data'->>'application_id'=o.application_id::text
 AND e.payload::jsonb->'data'->>'applicant_id'=o.applicant_id::text
 AND e.payload::jsonb->'data'->>'@type'=CASE e.routing_key
 WHEN 'offer.made' THEN 'type.googleapis.com/jobtrack.events.v1.OfferMade'
 WHEN 'offer.accepted' THEN 'type.googleapis.com/jobtrack.events.v1.OfferAccepted'
 WHEN 'offer.declined' THEN 'type.googleapis.com/jobtrack.events.v1.OfferDeclined' END
 AND e.payload::jsonb->>'occurred_at' ~ 'Z$'
 AND (e.payload::jsonb->>'occurred_at')::timestamptz=e.created_at) AS valid_published
FROM offers o JOIN outbox_events e
 ON e.payload::jsonb->'data'->>'offer_id'=o.offer_id::text
WHERE o.offer_id IN ('f0793e77-fa97-4c62-b6fb-36e912a2d7c1','f6c41c2e-7c08-4f7d-b829-b378668520fa')
GROUP BY o.offer_id,o.status,e.routing_key ORDER BY o.offer_id,e.routing_key;
SELECT application_id,applicant_id,employer_id FROM application_participants
WHERE application_id IN ('fdaf9cae-8af7-4c37-a6aa-aba413abbbc7','b7598dbb-4748-4a59-a663-f07f75c33ccb');
SELECT count(*) AS unpublished FROM outbox_events WHERE published_at IS NULL;
COMMIT;
```
